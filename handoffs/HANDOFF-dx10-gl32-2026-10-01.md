# Handoff: D3D10 and 32-bit OpenGL games (not released)

2026-10-01. Read after [HANDOFF-v0.7.7-2026-10-01.md](HANDOFF-v0.7.7-2026-10-01.md). None of this has been committed or
published; it is waiting for the in-game test.

## What went in

Add-on (`reshade`, on top of v0.7.7, same bridge protocol v5):

- **D3D10, 64 and 32 bits.** D3D10 only shares textures via legacy handles, which D3D12 cannot open. The back buffer goes
  first to a D3D11 device of ours on the game's adapter, through a texture that the game's device shares, and from there
  follows the D3D11 route as it is. Color only. `core/shared/d3d10_stage.h`, `core/transport/d3d10/D3D10Transport.inc`;
  `D3D11Transport.inc` gained `OpenBridge`, `Watchdog`, `ReadyToCross` and the `BridgePresent(dev, back, source, fromGame)`
  that both routes use.
- **32-bit OpenGL.** The 32-bit frontend creates a D3D11 device on the context's GPU (LUID) and the context imports the
  textures as `GL_HANDLE_TYPE_D3D11_IMAGE_EXT`; the frame crosses via blit with the default framebuffer, as in the 64-bit OpenGL
  route. Color only. `core/x86bridge/gl32.inc`, `routes32.inc`. D3D9 moved out of `frontend32.cpp` into
  `d3d9_32.inc` (the file dropped from 1048 to 762 lines; `line_limit_allow.json` follows).

Installer:

- `GraphicsApi.D3D10` (at the end of the enum). `d3d10.dll`/`d3d10_1.dll` in the import table become D3D10, and PCGamingWiki "10"
  too. D3D10 goes to the D3D11 presets (`Dx11`, `X86Dx11`), ReShade as `dxgi.dll`; the label is now
  "D3D10/D3D11 game". In the preference order it comes ahead of D3D9 (shares on the GPU).
- `Preset.X86OpenGL` (at the end of the enum): manifest "OpenGL" on the x86 route, 32-bit ReShade as `opengl32.dll`
  (`Engine.X86ProxyName`), in the card's 32-bit list. Texts in the 21 languages.

## After the in-game test

- **Just Cause 2 (D3D10, 32-bit) works.** It crashed on launch, with the add-on turned off: ReShade 6.8.0 hooks
  `D3D10CompileShader` in `d3d10.dll` and in `d3d10_1.dll`, calls the original from the wrong module and the two call each other until the
  stack runs out (dump: `d3d10_1+0x8426` / `d3d10+0x389c0` 18 thousand times). Both add-ons now restore to
  `d3d10.dll` its first bytes, read from the file on disk, in `init_device` and only with `d3d10_1.dll` loaded
  (`core/shared/d3d10_compile_unhook.h`). The hook only exists after a `LoadLibrary` by full path, so the
  fix does that load first. The `hostcheck` `d3d10` host now creates the device through `d3d10_1` and compiles through
  it: with the old add-on it gives `0xC00000FD`, with the new one it runs and composites the same.
- **Half-Life (OpenGL, 32-bit) works.** `hl.exe` deletes `opengl32.dll` from the folder on launch (`_unlink`, without checking).
  The installer writes the proxy read-only (`GameQuirks.Seal`); install and uninstall already clear the attribute first
  (`Engine.Writable`), and a transaction's rollback now clears it too.
- **`GameQuirks`** (`src/AmdNr.Core/Detection/GameQuirks.cs`): JC2 is D3D10 (the exe only imports `d3d9.dll`), GoldSrc
  (`hl.exe` with `hw.dll`) is OpenGL and keeps the proxy. A quirk takes precedence over the PCGamingWiki database.
- `hlds`, `hltv` and `srcds` no longer count as the game, and the 32-bit route picks the only exe that looks like the game in a
  folder with servers alongside it.
- An exe that imports `d3d9.dll` and mentions `d3d10.dll`/`d3d10_1.dll` in its own bytes gets a sentence in the "why"
  suggesting the D3D10/D3D11 route; the recommendation does not change.
- `ApiDbBuilder` was refused by PCGamingWiki (rate limit) when redoing the 168 "misses"; the database files
  were restored. Redo it calmly before the release.

## What was measured

- 32-bit and 64-bit probe (RX 9070 XT, Adrenalin 26.8.1): GL imports D3D11 textures by NT handle (`D3D11_IMAGE`,
  size 0 or w*h*4), KMT and D3D12, and the bytes cross in both directions.
- `hostcheck` gained the `d3d10` host. On the bench frame, 64-bit D3D10 = 64-bit D3D11 byte for byte; 32-bit D3D10 =
  OpenGL = D3D11 byte for byte; with a resize in the middle and with `Async=0` too; no host closes with an error. 64-bit D3D11
  after the refactor is identical to v0.7.7's (worktree). `host_check --cross` with 8 frames: all new routes
  "SAME within noise". x86-d3d9 comes out "DIFFERS" only because ReShade's capture returns X8R8G8B8 as BGRA; swapping
  R and B it matches at 0.09.
- Add-on gates: the MSVC ones pass; the 14 that require g++ C++20 fail because this machine's g++ is MinGW 6.3 (it was
  already like that). The static parts of the bridge tests run and pass. Installer: `gate.ps1 -Ui` 0 failures, 325 tests.

Not tested: a real game, MSAA on the 32-bit GL default framebuffer, GL context switched mid-game, D3D10 with
MSAA (comes out as drawn, colour only).

## lmxxf for RX 9060 (2026-10-01, not released)

`Engine.OwnedFolders` accepts `lmxxf-modules-gfx1200` (RX 9060 kernels that opti will start packaging alongside
`lmxxf-modules`), and the post-install message says "RX 9070 and RX 9060" only when the release ships files in that
folder. Already-published apps reject that name at install time, so in the opti release the 34 files of
`lmxxf-modules-gfx1200/` go into an on-demand component (like `mochizuki`), never into `optiscaler`.

## Favorites and library order (2026-10-02, not released)

Request from two players: favorite/pin games and put the ones with NR installed at the top. `GameEntry.Favorite` (saved in
`games.json`), `GameCard.Favorite` and `Library.SetFavorite`. Star in the corner of the cover (always visible when
favorited, on hover before that), in the side list, and "Add to/Remove from favorites" on right-click in both.
Filter menu: **Favorites** filter and **Favorites and installed first** (on by default, `Settings.LibraryPinnedFirst`,
null = on): favorites, then installed, then the rest, each group in the chosen order (name, recent,
added). `GameCard.OrderChanged` reorders when a game is favorited, installed or uninstalled. Strings
in 21 languages. New flow in `uishot` (order, saved in games.json, reverts on undo); `gate.ps1 -Ui` 0 failures.
Custom lists (multiple lists) were left out: favorites cover the requested "pin mode".
